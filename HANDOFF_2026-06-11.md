# QA Platform — Session Handoff & Next Steps
**Date:** 2026-06-11
**Scope:** Automated + manual test-runner reliability, authenticated crawling, issue-detection quality, and a recurring "Job not found / NaNs" failure.
**Purpose:** Hand-off for a follow-up discussion (with Fable) about the next phase of work.

---

## 1. System at a glance

- **Backend:** Flask (`backend/app.py`), MySQL via `flask_mysqldb`, Playwright (sync API) for crawling.
- **Frontend:** React + Vite (`frontend/src/pages/TestCases.jsx`), polls the backend.
- **Two run modes:**
  - **Automated** — `POST /run/<id>/async` → background thread (`backend/modules/runner/jobs.py`) runs `_perform_run` in `backend/modules/runner/routes.py`; the frontend polls `GET /job/<job_id>`.
  - **Manual** — headed Chrome (`backend/modules/runner/manual_run.py`); user logs in by hand, then auto-crawl from the authenticated page.
- **Authenticated crawling** — `backend/modules/projects/session_capture.py` captures cookies + localStorage + sessionStorage + landing URL during a manual "Open & Login"; the automated run replays them so the crawl runs as the logged-in user.
- **Checks performed per page:** broken links, console errors, missing alt text, SEO (title), security headers/HTTPS, accessibility (axe-core WCAG), mobile (tap targets / horizontal scroll).

---

## 2. Problems reported this session

1. **Terminal spam** — `--- Logging error ---` tracebacks during crawls.
2. **"Login ke baad bhi" requirement** — authenticated pages must be checked properly in *both* automated and manual modes.
3. **Issue-detection quality** — detect *real* issues, not "useless"/false-positive ones.
4. **`Error: Job not found` + `NaNs`** in the result modal after running Amazon without login.

---

## 3. Root causes found (data-backed)

| # | Symptom | Real cause |
|---|---------|-----------|
| A | `--- Logging error ---` in terminal | **Two causes.** (1) `RotatingFileHandler` rotation failing on Windows (`WinError 32`, file locked) — the dominant one; the Flask **debug reloader runs two processes** that both hold `app.log` open. (2) Console handler on Windows `cp1252` could choke on non-ASCII. NB: the original screenshot URL was pure ASCII, so rotation — not encoding — was the actual trigger. |
| B | Broken links flagged on authenticated pages | `check_broken_links` used bare `requests.head()` with **no browser cookies** → every login-gated link returned 302/401/403 and was wrongly "broken". Also many servers reject `HEAD` (403/405) even when the page is fine. |
| C | "Useless" mobile findings on authenticated crawls | Authenticated crawls run in a **desktop** viewport (to keep the session valid), but mobile checks (44px tap targets, horizontal scroll) still ran → pure noise. |
| D | Inflated issue counts / wrong health score | `merge_findings` had **no de-duplication** → the same footer link / missing header / a11y rule was counted **once per page**. |
| E | `Job not found` + `NaNs` | The async job registry is **in-memory** (`jobs.py`). The backend **restarted mid-crawl** (the debug reloader fires on every `.py` save — `app.log` shows ~130 restarts; the Amazon crawl died at page 41/75). The lost job → poll 404 → frontend error object had no `duration_ms` → `(undefined/1000).toFixed(1)` = `NaNs`. **Several of these restarts were triggered by our own edits while the dev server was running.** |

## 4. Fixes applied (all verified — see §5)

### Backend — `backend/logging_config.py`
- Force console stream to UTF-8 (`reconfigure(encoding='utf-8', errors='replace')`).
- New `_SafeRotatingFileHandler` that **swallows rotation failures** (re-opens the file, no traceback).
- File handler attached **only to the serving process** (skips the reloader supervisor via `WERKZEUG_RUN_MAIN`), removing the cross-process lock.

### Backend — `backend/modules/runner/routes.py`
- `check_broken_links` now forwards the **browser's cookies + real User-Agent** (tests links *as the logged-in user*) and **falls back to GET** when HEAD is rejected.
- "Broken" predicate refined: `401/403/429/503` are **no longer** treated as broken (auth / anti-bot / rate-limit / transient).
- `check_mobile` **skipped in desktop/authenticated mode** (`is_mobile=not session_used`).
- `merge_findings` now **de-duplicates** per category (broken link by URL, security by issue, a11y by rule+selector, etc.). Per-page detail is still preserved in `crawled_pages`.
- `navigate_spa` link matching is now **trailing-slash-insensitive** → more authenticated pages stay on the auth-preserving click-nav path instead of a hard reload.

### Frontend — `frontend/src/pages/TestCases.jsx`
- New `fmtSecs()` → shows `—` instead of `NaNs` when timing is missing.
- Poll 404 now returns a **clear message** ("the run was interrupted — backend restarted…") instead of "Job not found".
- Run-history duration is NaN-safe too.

## 5. Verification (executed, not claimed)

All fixes were exercised with throwaway harnesses run against real headless Chromium / local servers; results below.

- **Unit + component fixes (15/15 passed):** UTF-8 logging, rotation-failure swallowed (forced `os.rename` to fail), mobile skip on desktop, broken-link cookie+UA forwarding (monkeypatched `requests.Session`), 404/403/503/200 classification (local status server), `merge_findings` dedup, `navigate_spa` slash-insensitive click path.
- **End-to-end crawl (11/11 passed):** ran the **real `_perform_run`** against a controlled local site with deliberate issues (DB stubbed). Result: 4 pages crawled, `duration_ms=13017` (real, no NaN), `/dead` broken link detected and **deduped to 1** (it was on 2 pages), security issues **deduped to 2** (not 8), missing-alt + WCAG + SEO detected, **no false positives** on the valid 200 pages, valid health score, live progress callbacks fired.
- **Frontend:** parsed clean with `@babel/parser` (module + jsx).

> Tooling notes for future verification: backend harness runs with `backend/venv/Scripts/python.exe` (Playwright + chromium + network all work). Frontend has **no** esbuild/typescript installed — use `@babel/parser` for syntax checks. (Saved to project memory.)

## 6. Known limitations / open items (NOT yet addressed)

1. **Job durability (biggest gap).** Any backend restart still wipes in-flight + completed jobs. A long crawl (Amazon ≈ 75 pages, ~40 min) is fragile to *any* restart. Frontend now reports it gracefully, but the run is still lost.
2. **Authenticated crawl — real-world end-to-end not yet run.** All building blocks (cookie forwarding, session-preserving nav, desktop checks, sessionStorage replay, landing-URL warmup) are individually verified, but a full *real login → automated authenticated crawl* against a live SPA (e.g. DigiELV) has not been run this session.
3. **Crawl scope/perf.** Amazon queued 380+ URLs for a 75-page cap; many are near-duplicate product pages. No URL-pattern dedup or smarter frontier control.
4. **Manual run auto-trigger.** The 5-second "off-login → auto-crawl" timer can start crawling *before* login if the project's start URL isn't recognized as a login page. (Left as-is; flagged earlier.)
5. **Mobile findings dedup (cosmetic).** Same mobile issue type with different per-page counts ("3 tap targets…", "1 tap targets…") doesn't merge. Not a false positive; slightly repetitive.
6. **Health-score weights.** Now that duplicates are removed, scores will rise; weights may warrant re-tuning.
7. **`requests.Session` shared across the broken-link thread pool** — works in practice, but is a known thread-safety caveat worth noting.

## 7. Recommended next steps (for discussion)

Ordered by impact-to-effort. Pick based on what matters most.

### P0 — Make runs survive restarts (durability)
- **Option A (light):** add a MySQL `run_jobs` table; `jobs.py` writes job state there and `get_job` reads from it. Polls survive restarts; minimal new infra.
- **Option B (heavier):** move to Celery/RQ + Redis (separate worker process). Proper background-job semantics, but new infra to run.
- **Quick operational win meanwhile:** run the backend with the reloader off for real crawls (`use_reloader=False` / `flask run --no-reload`).
- *Recommendation:* Option A first — solves the actual pain (the "Job not found") with least overhead.

### P1 — Prove authenticated crawl on a real site
- Capture a real session via "Open & Login" on a live authenticated SPA, run an automated crawl, and confirm: `session_used=True`, sessionStorage injected, landing-page warmup lands past `/login`, and protected links are NOT flagged broken. This closes the one gap verification couldn't cover locally.

### P2 — Crawl frontier control / performance
- URL-pattern de-dup (e.g. collapse `/dp/<ASIN>` product pages), per-section caps, and/or parallel page testing to cut wall-clock and make `max_pages` meaningful on large sites.

### P3 — Detection polish
- Mobile-issue dedup by type; re-tune health weights post-dedup; refine console-error filtering (the 404-resource noise); decide policy on `alt=""` decorative images.

### P4 — Manual auto-trigger safety
- Make the manual auto-crawl button-only (no 5s auto-timer) so it never crawls before login. (One-line change; was offered, not yet applied.)
